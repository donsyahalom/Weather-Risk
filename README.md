# ☁️ WeatherMyTrip.com — MVP

Historical weather risk analysis for smarter travel planning.

**Stack:** Plain HTML/JS · Netlify (hosting + serverless functions) · Supabase (Postgres cache) · Open-Meteo (historical weather data)

| File / Folder | Why |
|---|---|
| `.env` | Contains real API keys and service-role secrets |
| `node_modules/` | Regenerated by `npm install` — 100+ MB of packages |
| `.netlify/` | Local Netlify dev cache |
| `*.local` | Any file ending in `.local` |

The `.gitignore` already excludes all of the above. Double-check with `git status` before every push.

## First-time setup — step by step

### Step 1 — Prerequisites

Install these tools if you don't already have them:

```bash
# Node.js v18+
node --version   # should print v18.x or higher

# Netlify CLI (for local dev)
npm install -g netlify-cli
netlify --version

# Git
git --version
```

### Step 2 — Clone or init the repo

**If starting fresh (no existing GitHub repo):**
```bash
# Navigate to the weathermytrip/ folder on your machine
cd path/to/weathermytrip

git init
git add .
git commit -m "Initial commit — WeatherMyTrip MVP"
```

**If you already have a GitHub repo:**
```bash
git remote add origin https://github.com/YOUR_USERNAME/weathermytrip.git
git branch -M main
git push -u origin main
```

### Step 3 — Install dependencies

```bash
npm install
```

This installs `@supabase/supabase-js` into `node_modules/` (used by the Netlify function). Netlify also runs this automatically on deploy via the `command = "npm install"` in `netlify.toml`.

### Step 4 — Set up environment variables

```bash
cp .env.example .env
```

Open `.env` and fill in your values:

```env
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGci...your-key...
OPEN_METEO_API_KEY=xMRyXTtxQvlTsZmd
```

Where to find each value:
- **SUPABASE_URL**: Supabase Dashboard → Your project → Settings → API → Project URL
- **SUPABASE_SERVICE_ROLE_KEY**: Same page → `service_role` key (click "Reveal")
- **OPEN_METEO_API_KEY**: Your Open-Meteo customer dashboard

> ⚠️ The `.env` file must **never** be committed. Verify `.gitignore` contains `.env` before you push.

### Step 5 — Run the Supabase migration

Go to your **Supabase Dashboard → SQL Editor**, open a new query, paste the full contents of `supabase/migrations/001_weather_cache.sql`, and click **Run**.

This creates:
- `weather_observations` table with indexes and RLS policies
- `locations` reference table (pre-seeded with Orlando and Miami)
- `cache_summary` diagnostic view

Verify it worked:
```sql
SELECT * FROM cache_summary;
-- Should return an empty table (0 rows — no data cached yet)
```

### Step 6 — Run locally

```bash
npm run dev          # = netlify dev, starts on http://localhost:8888
```

Open http://localhost:8888 in your browser. Select Orlando, pick a date range, and click **Analyze Risk**.

> **First request per city:** The function will detect an empty cache, fetch 20 years of data from Open-Meteo (~7 300 rows), and upsert it into your Supabase project. This takes **10–25 seconds** and only happens once per location. All subsequent requests read from Supabase and respond in under a second.

Verify the cache populated:
```sql
SELECT * FROM cache_summary;
-- Should now show ~7 305 rows for 'orlando'
```

## Deploy to Netlify

### Connect your GitHub repo

1. Push your code to GitHub (Step 2 above).
2. Go to [app.netlify.com](https://app.netlify.com) → **Add new site → Import an existing project**.
3. Choose **GitHub**, authorize, and select your `weathermytrip` repository.
4. Netlify auto-detects `netlify.toml`. Leave build settings as-is and click **Deploy site**.

### Add environment variables in Netlify

In your Netlify site → **Site configuration → Environment variables**, add the same three variables from your `.env`:

| Key | Value |
|---|---|
| `SUPABASE_URL` | `https://YOUR_PROJECT_REF.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | `eyJhbGci...your-key...` |
| `OPEN_METEO_API_KEY` | `xMRyXTtxQvlTsZmd` |

After adding them, trigger a redeploy: **Deploys → Trigger deploy → Deploy site**.

### Subsequent deploys

Every push to `main` triggers an automatic redeploy. The Supabase cache persists between deploys — no re-fetching needed.

## Function timeout warning

The Netlify free tier has a **10-second function timeout**. The first-run cache population for a new location can take 10–25 seconds. If it times out:

1. The partial upsert is idempotent (safe to retry).
2. The next request will pick up where the previous one left off.
3. After 2–3 retries the cache will be fully populated.

**To avoid this on production first launch:** Run `npm run dev` locally first. The Netlify function connects to the same Supabase instance, so the cache you populate locally is ready immediately in production.

Upgrade to Netlify Pro for a 26-second timeout if you need guaranteed single-request population.

## Supabase cache management

Check cache status:
```sql
SELECT * FROM cache_summary;
```

Force a re-fetch for one location (e.g., to extend `END_YEAR`):
```sql
DELETE FROM weather_observations WHERE location_key = 'orlando';
-- Then reload the page — the function will repopulate
```

## How it works

1. User fills in destination, date range, and risk threshold in the browser.
2. The frontend POSTs to `/.netlify/functions/analyze`.
3. The function checks Supabase for cached data.
   - **Cache hit** → reads filtered records, returns JSON in ~200 ms.
   - **Cache miss** → fetches 20 years from Open-Meteo, upserts into Supabase, returns JSON in ~15–25 s.
4. The frontend receives raw daily records and runs all statistics client-side:
   - Recency-weighted percentiles, Normal and Gamma distribution fits
   - Independence composite model for daily joint risk
   - Binomial trip-level risk for joint, heat-only, and weather-only components
5. Charts, PDF visualizations, and the data table render immediately.

The Open-Meteo API key is **never exposed to the browser** — it lives only in Netlify environment variables.

## Adding new cities

1. Add the location to `LOCATIONS` in **both**:
   - `netlify/functions/analyze.js`
   - `public/index.html` — add an `<option>` to the `<select id="location">` element
2. Insert a row into Supabase:
   ```sql
   INSERT INTO locations (key, display_name, latitude, longitude, timezone)
   VALUES ('tampa', 'Tampa, FL', 27.9506, -82.4572, 'America/New_York');
   ```
3. The first browser request for the new city auto-populates its 20-year cache.

## Statistical model

| Component | Distribution | Threshold |
|---|---|---|
| Heat risk | Normal(μ, σ) → CDF | max temp > 35°C / 95°F |
| Heavy rain | Gamma(α, β) → CDF | precipitation > 25 mm/day |
| Thunderstorm | Bernoulli(p) | WMO codes 95, 96, 99 |
| High wind | Bernoulli(p) | max wind > 50 km/h |
| Daily joint risk | Independence composite | `P = 1 − ∏(1 − pᵢ)` |
| Trip risk | Binomial(N, p) | `P(X ≥ k)` — three variants: joint, heat-only, weather-only |

**Recency weighting:** `w_year = exp(−0.1 × (currentYear − year))` — 2024 data has ~3× the influence of 2014.

**Default risk threshold:** `k = ⌈0.60 × N⌉` where N = number of days in the date range. Editable in the UI.
